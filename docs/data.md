# 数据与统计口径

改采集、汇总、成本前先读这份。核心原则：**读不到 ≠ 0**，**占用 ≠ 有效**。

## 测量语义

| 值 | 含义 | 能否进平均 |
|---|---|---|
| `0` | 真实测到 0 | 计入 |
| `null` / 缺失 | 没读到 | **不计入** |

- 平均的分母是**报了数的样本**，不是持有数。空值拖低平均是事故（曾把 73% 算成 41.7%）。
- 利用率用**时间平均**（如用户页取近 5 分钟），不是单次瞬时值再平均；瞬时采样对一阵一阵的负载不可靠。
- 掩码 / 时钟等辅助字段读不到存 `null`，禁止写成 `0`。

## 探针与解析约束

- 远程探针只读、单次 awk 解析（控制 fork 次数）。
- **`ps` 用户名列必须带宽度**（`user:32=`）。多列 `ps` 默认 8 字符会把 `luzhicheng` 截成 `luzhich+`，账目会拆成两个人。
- **`pmon` 按表头列名定位**，不能硬编码列数（驱动 535=8 列，580/610=10 列）。
- CPU 用两次采集的 `/proc/stat` 差值，不在目标机 sleep。

## 用量三指标

| 字段 | 含义 | 口径 |
|---|---|---|
| `gpu_seconds` | 占用 GPU 时 | 占着卡就计，按 `distinct` 卡计数 |
| `sm_gpu_seconds` | 有效 GPU 时 | SM 利用率对时间积分；共享卡按 100% 封顶 |
| `mem_mib_seconds` | 显存积分 | 容量压力 |

- **利用率归因**：单用户独占一张卡时，该卡的利用率取卡级 `utilization.gpu` 与进程 SM 的较大者——并行任务会把不计算的伴随进程留在卡上，pmon 进程 SM 求和会低估（实测 gpu16 GPU0：卡 70% 而两进程 SM 合计 38%）。共享卡仍按各用户进程 SM 切片、单用户封顶 100%。进程 SM 读不到且卡级 util 也是 0 时**不计入**样本（0 与「落在爆发间隙」无法区分）；进程 SM 读不到但卡级 util > 0 时用卡级值。

- **写入时累计**进 `usage_rollup` / `host_hourly` / `usage_peak`，**永不清理**；原始 `*_sample` 按 `raw_retention_hours` 清理。
- 每样本最多计入 `2 × interval`；停机间隙不补记。
- 「同时使用峰值」跨机器，存 `usage_peak`（单机 `MAX(peak_gpus)` 会少算）。用量 UI 可不展示，但后端继续累计。
- 跨时间识别用 `bus_id` / UUID，不用会重排的 GPU 序号。

## 成本

- 价目在独立的 `config/prices.json`（与 `hosts.json` 解耦），热重载。
- **只用当前价**：`占用成本 = gpu_seconds/3600 × 当前单价`，查询时乘，改价即整段历史重算。库内不存金额。
- 键 = `nvidia-smi` 原始型号名；型号存永久的 `hosts.gpu_name`。
- 未定价 → `cost_yuan: null` + `unpriced_gpu_hours`，**绝不当 0**。
- 成本是实验室内部科研算力粗算，不是真实计费；不在页面上堆免责声明。

## 展示口径（用量页）

- 三指标并排；占用高、有效低本身就是信号。
- 成本列是主数字（主题色 + 加粗）；未定价单独标出小时数。
- **不展示** 同时使用峰值、合计 footer。
- 刷新最多每小时一次 + 手动「立即刷新」；区间切换立刻拉数；新鲜度一行以内。

## 告警与健康

- 状态灯由时间戳**实时推导**，不在采集时锁存。
- 失联机数据必须置灰并标注陈旧时间；过期数据不得当实时展示。
- 卡数变化写事件；角标告警与机器自己近期基线比（固定 `expect_gpus` 配了才用）。
- 降频：只报热降频 / 硬件降频（`THROTTLE_BAD_BITS`），**不含功耗墙 `0x004`**。
- 热降频看**近 1 小时窗口**（瞬时掩码会跳）；样本不足显示 `—`，不显示 `0%`。
- 热降频起始 80°C 来自实测（非规格书），改阈值时注明来源。

## 校验与契约

- 配置：`server/config-schema.ts`；接口：`shared/schema.ts`。schema 只校验，不做默认值/改名（管理页需原样回写）。
- 前端类型用 `z.infer`，收到 SSE 先过 schema，禁止再手写平行 interface。
- 配置热重载写坏时**保留旧配置**并记日志，不崩服。
- 管理页保存带 `revision` 指纹，冲突返回 409，禁止静默覆盖。

## 数据修复

- 可修复的前提是**卡级数据未丢**且能证明归属；修复写的是实测值，不猜。
- 判定「该小时进程数据全丢」= 该小时所有 `sm_pct` 都是 `null`（真实空转是 `0`）。
- **保留期内可回算**：原始样本还在的整点小时，`sm_gpu_seconds` 可按当前利用率归因重放积分（`repairUnderstatedSm`）。含最老样本的那个残缺小时**不碰**——覆盖会丢掉已 prune 的部分。再早的小时只剩 rollup，修不了。
- 用户名合并：仅当唯一更长名以截断名为前缀才合并，且**累加**到全名行；歧义保持原样并报告。
- 回填 / 迁移走 `server/db/repairs.js`；清理 DELETE 必须有 `ts` 打头的索引，否则明细则 30 天会扫表。
