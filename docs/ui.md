# 界面规范

数据看板，不是介绍页。改 UI 前先读这份。

## 布局

- 一机一段：**一行机器摘要 + 一张 GPU 表**。一卡一行（一进程一行），空闲卡也占行并标「空闲」。
- 页头单行：校徽 + 站点名 + 页签 + 轮询状态 + 主题开关；窄屏靠 `flex-wrap`，任何宽度不横向溢出。
- 展开详情默认收起；图表放在展开区顶部（开关的意义就是看趋势）。
- 磁盘每个文件系统一个方块；网络挂载是**整行状态带**（固定短列表，不与磁盘同构）。
- 显示顺序 = `config/hosts.json` 里 `hosts` 数组顺序。

## 页面上不放说明性文字

判断规则：**会随状态变化的信息留下，不变的说明移走**（悬停提示或文档）。

- 不写「本系统经 SSH 采集……」这类页脚介绍。
- 括号说明改成 tooltip。
- 允许保留的是**状态**：如「另有 N 项未选」「N 项异常」。

## 颜色语义

告警色阶（绿→琥珀→红）**只留给坏掉或即将坏掉的读数**。

| 指标 | 用色 | 说明 |
|---|---|---|
| 磁盘占用、系统内存 | 告警色阶 | 满 / 耗尽会杀任务 |
| 温度 | 达降频点转红 | 性能正在被丢掉 |
| 显卡利用率、显存、CPU | 中性 | 在用是目标，不是故障 |

- 状态灯必须**带文字**，不能只靠颜色。
- 颜色来自 antd token / CSS 变量，禁止硬编码色值（有测试盯着）。
- **利用率方向**：用户占用效率是「低才标」（`efficiencyColor`），与资源压力 `severity`（高=红）是两个问题，不要混用。
- **不给功耗墙告警或着色**；热降频 / 硬件降频才是问题。
- 空闲卡不报降频；掩码读不到存 `null`，不存 `0`。

## 实时刷新

- 切回后台标签页**直接跳到最新快照**，不回放中间状态（`useSnapshot` 用 rAF 合帧 + 可见时拉 `/api/snapshot`）。历史查询去「事件 / 用量」页，实时看板只显示现在。

## 表格

- 界面显示 **GPU 序号**；跨时间识别用数据里的 PCIe 槽位 / UUID。
- 可展开行：点整行任意处展开；管理页表格**不要**开点行展开（单元格是输入框）。
- **带展开行的 Table 不能同时用 `scroll={{ x: 'max-content' }}`**（展开后列宽会塌成 0）。
- 用户页展开行显示「已运行」；同一读数在机器页 / 用户页用色必须一致。
- 型号用 `display_name`（短名），正常字号正文色。

## 主题

- 三态：自动 / 亮 / 暗，默认自动（`prefers-color-scheme`），选择存 `localStorage`。
- 颜色全部走 CSS 变量；`index.html` 预绘制脚本与 `theme.ts` 的 storage key 必须一致。
- 校徽放在两种主题下都保持浅色的底片上，不改校徽配色。

## 图表

- 一机一图 + 指标选择器 + 时间档位（24h / 3d / 7d / 30d），不要并排多图。
- 30 天档只用 `host_hourly`（永不清理），不用原始采样。
- 边距按标签实测量：`left: 0`、`top: 10`、`right: 30`（防止「100%」和末刻度被裁切）。
- 空闲小时记 0%，不画成断线。

## 检查清单

1. `npm test && npm run typecheck && npm run check:render`
2. `npm run screenshot`（必要时 `--tabs`、`--expand`）看图
3. 关注：告警色是否只用于故障、是否出现说明文字、是否 `undefined`/`NaN`、细线颜色用计算样式确认（缩略图会失真）
